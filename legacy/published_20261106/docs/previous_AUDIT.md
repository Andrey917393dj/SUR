# Аудит — прогон всех функций ×20

Место: `8540168650` · игрок: `FrigoCamelo1502` · стенд: `SPTW_R` (Godly, A+)
Метод: `getgenv().ArcticAPI.audit` внутри живого клиента, по 20 итераций на функцию.
Каждая итерация — реальный вызов, между итерациями выдерживается кулдаун мува.

## Критерий PASS

Не «не упало». Два уровня доказательства:

| Класс мува | Критерий PASS |
|---|---|
| M1, Q, E, R, G, H, Y, N | сервер прислал акк `ReplicatedStorage.Events.CoolDownGUI` |
| X, T, Z, F, J | `press()` вернул `true` — акка у этих мувов не существует |

Почему так: акк присылают только 8 мувов из 14. У остальных сервер молчит
по дизайну (условные/утилитарные), и ждать акк — значит ловить ложный FAIL.
Это доказано диагностикой: `press=true, err=nil, ack=nil` для X/T/Z/F/J,
при этом `press=true, ack="Heavy Punch"` для R.

## Что из этого следует

**M1 не баг, а механика.** Пять ударов проходят, шестой сервер дропает —
это комбо-лимит. 17/20 — потолок для спама, а не поломка. При зазоре 0.85s
картина та же (падает на #4, #10, #16), значит дело не в скорости нажатий,
а в счётчике комбо.

**`E` и `R` — 19/20 из-за одного сетевого таймаута.** Обе сорвались на
итерации 13, в один и тот же момент. `press` ушёл, акк не вернулся.

**У `X`, `T`, `Z`, `F`, `J` акка нет вообще** — сервер не подтверждает
эти мувы через `CoolDownGUI`. Для них PASS считается по успешному `press()`.
